# 🎯 گردش‌کار: از رول بازیکن تا کسر تلفات

> مسیر کامل: بازیکن رول می‌نویسد → من گزارش تلفات می‌سازم → تو کپی/پیست می‌کنی → بات کم می‌کند.

---

## گردش‌کار عملی

```
۱. بازیکن رول عملیاتش را می‌نویسد
          ↓
۲. تو رول را برای من می‌فرستی
          ↓
۳. من گزارش تلفات استاندارد می‌سازم  ← اینجا کار من است
          ↓
۴. تو کپی می‌کنی
          ↓
۵. پنل ادمین → 💥 مدیریت تلفات → 📄 ثبت تلفات (پیست گزارش آماده)
          ↓
۶. پیست → پیش‌نمایش → ✅ تأیید
          ↓
۷. بات کسر می‌کند + فاکتور رسمی خودکار برای بازیکن می‌فرستد
```

---

## چه چیزی به من بده تا خروجی دقیق باشد

**حداقل لازم:**
- متن رول بازیکن
- **کشور مهاجم و کشور مدافع**

**اگر داری، خیلی کمک می‌کند:**
- شدت نتیجه‌ای که مدیریت تعیین کرده (مثلاً «حمله موفق بود» / «نیمه‌موفق» / «دفع شد»)
- آیا زیرساخت هم هدف بوده؟
- چند روز/موج طول کشیده؟

**اگر نگویی، من خودم بر پایه‌ی منطق نظامی تصمیم می‌گیرم** و در توضیح می‌نویسم چرا هر عددی را انتخاب کرده‌ام — تو می‌توانی هر عددی را قبل از پیست تغییر بدهی.

---

## نکته‌ی مهم: من همیشه هر دو طرف را می‌سازم

یک حمله همیشه **دو گزارش** دارد:

| گزارش | برای چه کسی | شامل چه چیزی |
|---|---|---|
| **مدافع** | کشوری که حمله شده | تجهیزات نابودشده، تلفات انسانی، خسارت زیرساخت |
| **مهاجم** | کشوری که حمله کرده | موشک/پهپاد مصرف‌شده، هواگرد ساقط‌شده، **هزینه‌ی عملیات** |

اگر فقط مدافع را ثبت کنی، مهاجم بدون هیچ هزینه‌ای حمله می‌کند و بازی نامتعادل می‌شود. مهمات مصرف‌شده باید از انبار مهاجم کم شود.

مگر اینکه بگویی فقط یکی را می‌خواهی.

---

## قواعدی که همیشه رعایت می‌کنم

**۱. سقف واقع‌گرایانه در یک عملیات**

| نوع هدف | نرخ تلفات |
|---|---|
| هدف اصلی عملیات | تا ۴۰٪ |
| هدف درجه‌دو | تا ۲۵٪ |
| هدف فرعی | زیر ۱۰٪ |

**۲. ثابت و بزرگ → نرخ بالا. متحرک و پراکنده → نرخ پایین.**
رادار ثابت ۲۳٪ می‌خورد، تور-M1 متحرک ۲۰٪، قایق تندرو پراکنده ۲٪.

**۳. باارزش‌تر → نرخ بالاتر**، حتی اگر تعدادش کم باشد. اطلاعات روی گران‌ترین سلاح متمرکز می‌شود.

**۴. مجروح ≈ ۲ تا ۴ برابر کشته.** این مهم‌ترین شاخص واقع‌گرایی است.

**۵. همیشه چیزی باقی می‌گذارم.** بازیکنی که همه‌چیزش نابود شود، از بازی می‌رود.

**۶. هیچ‌وقت بیشتر از موجودی نمی‌نویسم** — بات کل گزارش را رد می‌کند.

## ابزار بررسی (اختیاری، برای اطمینان)

قبل از پیست می‌توانی گزارش را شبیه‌سازی کنی — روی دیتابیس واقعی بازی اثر ندارد:

```bash
# فهرست کشورها
python tools/loss_tool.py countries

# انبار پایه‌ی یک کشور از config
python tools/loss_tool.py list yemen

# انبار فعلی از snapshot خواندنی دیتابیس بازی (مسیر پیش‌فرض config.DB_PATH)
python tools/loss_tool.py list yemen --live
python tools/loss_tool.py list iran --live --cat Navy

# اگر دیتابیس در مسیر دیگری است؛ منبع اصلی فقط read-only خوانده می‌شود
python tools/loss_tool.py export yemen --live --db /data/game.db

# پیدا کردن نام دقیق یک تجهیز در موجودی فعلی
python tools/loss_tool.py find yemen "قایق نذیر" --live --db /data/game.db

# شبیه‌سازی کامل روی snapshot؛ حتی در حالت live دیتابیس اصلی تغییر نمی‌کند
python tools/loss_tool.py check yemen report.txt --live --db /data/game.db --render
```

حالت پیش‌فرض (`بدون --live`) برای بررسی کاتالوگ و مقادیر پایه‌ی config است. برای گزارش واقعی که باید با موجودی فعلی بازیکن تطبیق داشته باشد، از `--live` استفاده کن. در این حالت ابزار دیتابیس اصلی را با SQLite در حالت read-only می‌خواند و یک snapshot موقت می‌سازد؛ بنابراین `check` روی snapshot اجرا می‌شود و دیتابیس اصلی را تغییر نمی‌دهد.

خروجی `check` نشان می‌دهد:
- هر قلم به چه تجهیزی تطبیق می‌خورد و **چند درصد** موجودی است
- چه چیزی ناشناخته می‌ماند
- نسبت مجروح/کشته منطقی است یا نه
- خزانه/نفت/پرسنل بعد از اعمال چقدر می‌شود
- آیا گزارش رد می‌شود یا نه

## فرمت گزارش (برای مرجع)

```
📄 تلفات تجهیزات 🇾🇪 یمن — عملیات «نام عملیات»
━━━━━━━━━━━━━━━━━━

⚓ عنوان دسته

⚓ نام دقیق تجهیز
تلفات: ۱۵ فروند
---

📌 جمع تلفات ثبت‌شده:

⚓ شناورها: ۱۵ فروند

━━━━━━━━━━━━━━━━━━

👥 تلفات انسانی

🪖 نیروهای نظامی (کشته): ۴۸ نفر
🏥 مجروحان: ۱۴۰ نفر
👤 غیرنظامیان (کشته): ۱۸ نفر

💸 هزینه آماده‌سازی عملیات
💵 هزینه مالی: ۴۰۰,۰۰۰ دلار
🛢️ سوخت مصرفی: ۱,۲۰۰ بشکه

🟠 وضعیت: تلفات ثبت شد.
```

**قواعد فنی:**
- نام تجهیز در یک خط، `تلفات: عدد واحد` در خط بعد
- نام باید **دقیقاً** مطابق انبار کشور باشد (وگرنه نادیده گرفته می‌شود)
- اعداد فارسی و لاتین هر دو کار می‌کنند
- «حدود / تقریباً» پشتیبانی می‌شود
- هزینه فقط از بخش «هزینه آماده‌سازی» خوانده می‌شود
- اعمال **اتمیک** است: یا همه، یا هیچ‌کدام

## اگر اشتباه ثبت شد

پنل ادمین → مدیریت تلفات → 📋 تاریخچه → انتخاب گزارش → **↩️ بازگردانی**

همه‌چیز کامل برمی‌گردد: تجهیزات، کلاهک، طلا، تراشه، خزانه، نفت، پرسنل، ساختمان و درآمد روزانه.
